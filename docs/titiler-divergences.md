# Intentional Divergences from TiTiler 2.4.1 / GDAL

`cogzilla` targets drop-in compatibility with TiTiler 2.4.1 wherever parity benefits clients. However, whenever TiTiler, `rio-tiler`, GDAL, or FastAPI makes a correctness, performance, or ergonomics compromise, `cogzilla` intentionally chooses the better behavior rather than replicating the compromise.

This document is the living record of every intentional divergence, **why** it exists, **what it means for clients**, and how to opt out when applicable.

---

## 1. Accuracy, Correctness & Performance Improvements Over TiTiler / GDAL

### 1.1 Exact Analytical Coverage-Weighted & Ellipsoidal Area-Weighted Zonal Statistics (`POST /*/statistics`, PR #165)

- **TiTiler / `rio-tiler`:** Uses a binary pixel mask by default (overcounting thin slivers up to 5× and small/diagonal shapes), or an approximate `cover_scale=10` 10× supersampled rasterization (100× larger temporary boolean grid in RAM, still approximate). Pixel means are unweighted in the raster's CRS plane, which over-weights northern pixels by up to **53%** on a `40°N–60°N` polygon in `EPSG:4326`.
- **`cogzilla`:** Computes **exact analytical pixel coverage fractions** in `[0, 1]` directly on the COG's native pixel grid (zero resampling, Green's-theorem edge traversal in `O(V + perimeter_cells)` + linear scanline fill), multiplied by each pixel's **WGS84 ellipsoidal ground area** (`w = cov × area_px`):
  - `count`: exact sum of pixel coverage fractions for polygons (pixel units, snapped to integer within `1e-6`), exact clipped length in pixels for `LineString`/`MultiLineString` (e.g. `141.42` for a 100-px diagonal), or point count (`1.0` per point) for `Point`/`MultiPoint`.
  - `sum`: coverage-weighted sum of valid pixel values.
  - `area`: exact ellipsoidal ground area in `m²` covered by valid data for polygons; `null` for `Point`/`MultiPoint`/`LineString`/`MultiLineString` (points and lines have no area).
  - `length`: exact WGS84 geodesic length in metres for `LineString`/`MultiLineString` features (omitted for polygons/points).
  - `mean`, `std`, `median`, `percentiles`: weighted by `w = cov × area_px` for polygons (or geodesic segment length for lines) when `?area_weighted=true` (default), or `w = cov` when `?area_weighted=false`.
  - `histogram` (numeric and categorical) & `categories`: always reported in **coverage units** summing to `count` regardless of `area_weighted` (so integer class counts never become area-redistributed non-integers). For categorical polygon queries, a sibling `category_areas` map reports the exact ellipsoidal ground area in `m²` per class (summing to `area`).
    - Bins (2026-11-26): only the counts differ. The bin edges, and the bin each value goes to, are `numpy.histogram`'s on every statistics route (`GET` and `POST`, `/cog`, `/stac`): edges are `linspace(first, last, n + 1)`, worked in float32 for a float32 band (or an expression numexpr keeps in float32) and in float64 otherwise; a band of one value is widened by `0.5` each side; a band with no valid pixels gets `0 .. 1`; a value on an inner edge goes to the bin above it and the last bin keeps its upper edge; values outside `histogram_range` or custom `histogram_bins` edges are left out. When the GPU samples and reduces a band itself (the values never reach the CPU), its counts are kept against these edges, so a value lying exactly on an inner edge can be counted one bin low there.
  - Boundary precision: vertices within `1e-6 px` of grid lines are snapped before clipping, and pixel-set statistics (`valid_pixels`, `masked_pixels`, `valid_percent`, `min`, `max`, `unique`, `majority`, `minority`, categorical keys) exclude negligible CRS round-off touches (`cov ≤ 1e-6`) while weighted sums retain all slivers (`cov > 1e-12`).
  - `?cover_scale=` and `?all_touched=` are accepted and ignored (since exact coverage is already strictly more accurate and faster).
- **Client significance:** Strictly more accurate (max error `≤ 8.55e-9` px on analytic shapes vs up to 5× error on binary masks), zero supersampling RAM blowup, and **2.3×–7.9× faster** than in-process `rio-tiler`/GDAL even over HTTP:

| Workload (native grid, `bidx=1`, `max_size=0`) | `cogzilla` HTTP (exact + ellipsoidal) | `rio-tiler`/GDAL mask (in-process) | `rio-tiler`/GDAL `10×` cov (in-process) |
|---|---:|---:|---:|
| Sliver `0.2×100` (true `20.00 px`) | **0.19 ms** (`20.00`) | 0.28 ms (`100.00`) | 0.35 ms (`100.00`) |
| `100×100` triangle (true `5,000.00 px`) | **0.29 ms** (`5,000.00`) | 0.54 ms (`5,149.00`) | 1.62 ms (`5,005.00`) |
| `1M px` square (true `1,000,000.00 px`) | **24.62 ms** (`1,000,000.00`) | 85.99 ms (`1,000,000.00`) | 195.08 ms (`1,000,000.00`) |
| `10k`-vertex circle (true `282,743.34 px`) | **12.18 ms** (`282,743.32`) | 28.15 ms (`283,876.00`) | 95.19 ms (`282,743.40`) |

- **Opt-out:** Pass `?area_weighted=false` to disable ellipsoidal ground-area weighting and compare directly against CRS-plane coverage-weighted statistics (for small UTM/equal-area polygons, `area_weighted=true` and `false` are automatically identical via a `< 1e-6` Jacobian short-circuit).

### 1.2 Exact Affine Handling for Rotated GeoTIFFs (`F4`)

- **TiTiler / GDAL:** On rotated geotransforms, tile reads disagree with the file's own affine transform (measured `z11` mean error `2,618` on a `50,000` value range; `z9` mask `86%` agreement).
- **`cogzilla`:** Evaluates the full 6-parameter affine transform directly (`z11` **100%** of pixels identical to ground truth; `z9` mask **100%** agreement).
- **Client significance:** Rotated satellite scenes and drone orthomosaics render in the exact right geographic location without warp artifacts.

### 1.3 Ground-Resolution Overview Selection for Polar & Antimeridian Tiles (`H1b`, `H2b`, PR #161)

- **TiTiler / GDAL:** Oversamples polar (`EPSG:32661` UPS) and antimeridian rasters by reading full resolution even when a coarse overview already exceeds the tile's ground resolution (e.g. `ups.tif` at `977 m/px` for WebMercator `z3/6/0` needing `1,688–3,676 m/px`).
- **`cogzilla`:** Selects the overview matching the tile's actual required ground resolution (`ups.tif` `z3/6/0` reads the `2×` overview in **5 ms** vs TiTiler's **11 ms** full-res read).
- **Client significance:** Less I/O, lower latency, less aliasing, and no loss of accuracy.

### 1.4 Polar & LAEA Rasters in Foreign TileMatrixSets (Sweep #12)

- **TiTiler / GDAL:** Reprojecting polar and Lambert Azimuthal Equal-Area (`EPSG:3035`, `3031`, `3413`, UPS) files into foreign grids (`WorldCRS84Quad`, `WebMercatorQuad`, `CanadianNAD83_LCC`, `NZTM2000Quad`, UPS) matches the source file on `93–98%` of pixels.
- **`cogzilla`:** Matches the source file on **~100%** of pixels.
- **Client significance:** Higher geometric fidelity across non-Mercator tile grids.

### 1.5 Area-Exact `resampling=average` & `mode` (`L1`, PR #167)

- **TiTiler / `cogzilla` (prior):** `cogzilla` now integrates over the exact destination pixel footprint `[x0, x1] × [y0, y1]` weighted by exact overlap area:
  - `1:1` overview reads sample the exact single pixel (`0.0` RMS, zero blur).
  - Exact `2×` / `4×` / `8×` reductions equal the exact full-resolution `k×k` block mean / mode to `< 1e-6` even on COGs without overviews.
  - Non-integer factors weight every overlapped source pixel by its exact overlap area.
- **Client significance:** Physically area-true downsampled previews and tiles.

### 1.6 Terrain Hillshade & Slope as TiTiler's, with Seamless Full-Size Tiles (`N2`, Sweep #45)

- **TiTiler:** Takes numpy's gradient (the centred difference, one-sided on an array's edge). `hillshade` uses it per pixel and writes `255·(shaded + 1) / 2`. `slope` divides it by the transform's pixel size in the grid's own units (Web Mercator metres on a tile, degrees on a box in degrees). Both crop their `buffer` (3 by default) from the image they were given, so a tile is `250×250` (`970×970` for `976×976`) unless the caller adds `buffer=3`. With pixels that are not square, `slope` divides the gradient down the rows by the width of a pixel and the one across by its height.
- **`cogzilla`:** The same gradient, shading and pixel size, so tiles, boxes, previews and features are TiTiler's to within one level of truncation (slope exactly) (2026-11-27; until then cogzilla used gdaldem's Horn stencil over ground metres, 12 to 36 dB from TiTiler's pictures). Two things are not followed. Every output stays full-size (`256×256`) and seamless: the 1-pixel neighbour halo is read rather than cropped, so a tile is TiTiler's `buffer=3` tile, and the inner pixels of a box or preview are TiTiler's cropped ones. A pixel beside nodata, or with `buffer` 0 on a tile's edge, takes numpy's one-sided difference from the neighbour it has, where TiTiler masks it or reads no further than its own image. Each axis's gradient is divided by that axis's pixel size. When a TiTiler client passes `?algorithm=hillshade&buffer=3` or `?algorithm=slope&buffer=3`, `cogzilla` subtracts the default crop of 3 px so it still outputs `256×256`, as TiTiler does.
- **Client significance:** TiTiler's hillshade and slope, with the same `z_exaggeration`, without 250×250 slippy-map tiles, tile-boundary seams or a lost ring of pixels along coastlines.

### 1.7 Legacy GeoJSON `crs` Member & Safe `400` on Projected Coordinates Without `coord_crs` (`L2`, PR #167)

- **TiTiler:** Sending projected GeoJSON coordinates (e.g. UTM metres) to `POST /cog/statistics` or `POST /cog/feature` without `?coord_crs=` triggers a `500 Internal Server Error` attempting to allocate hundreds of terabytes.
- **`cogzilla`:**
  1. Honours legacy GeoJSON 2008 `"crs"` members (`type: "name"` or `type: "EPSG"`) on Geometry, Feature, and FeatureCollection when `?coord_crs=` is omitted.
  2. If neither `?coord_crs=` nor `"crs"` is provided and coordinates fall outside WGS84 lon/lat bounds (`[-360, 360] × [-90, 90]`), returns **`400 Bad Request`** with an explicit hint to pass `?coord_crs=EPSG:<code>`.
- **Client significance:** Never OOMs, supports legacy CRS-tagged GeoJSON out of the box, and gives immediate actionable feedback when `?coord_crs=` was forgotten.

### 1.8 Proxy Headers, HTTP Caching, Content Negotiation & Extra Endpoint Flexibility (Sweeps #10–#11, #45)

- **`X-Forwarded-Proto`, `X-Forwarded-Host`, `X-Forwarded-Prefix`:** Honoured when constructing TileJSON, WMTS, and landing/viewer URLs (TiTiler ignores them), with strict validation rejecting protocol-relative prefixes (`//...`) and invalid host authorities.
- **Conditional requests, `ETag`, `HEAD`, and `Vary: Accept` (Sweep #45):** Image responses emit `ETag` (reflecting all render parameters) and `Cache-Control`, returning `304 Not Modified` on exact, strong-form, or `*` `If-None-Match` with `ETag` and `Cache-Control` preserved (TiTiler sends no `ETag` and answers `200`). `HEAD` on tiles and metadata routes returns `200` with headers and no body (TiTiler returns `405`). All HTML-negotiated routes (`/`, `/conformance`, `/tileMatrixSets`, `/colorMaps`, `/algorithms`, and OGC tileset endpoints) send `Vary: Accept` (TiTiler sends only `Vary: Origin`, risking shared-cache confusion between browser HTML and API JSON).
- **CORS preflight & trailing slashes:** `OPTIONS` preflight returns `204 No Content` (vs TiTiler `200`), and trailing slashes (e.g. `/cog/info/`) are served directly (`200`) without a `307` redirect.
- **Flexible STAC expressions, `contours`, `histogram_bins`, and convenience routes:**
  - `POST /*/feature` accepts `FeatureCollection` and bare `Geometry` in addition to `Feature` (TiTiler returns `422`).
  - `reproject=gauss` is supported as a resampling extension (TiTiler returns `422`).
  - STAC `expression=` auto-infers referenced assets (no redundant `?assets=` required) and supports both `asset_b1` and `asset_as_band=true` syntax.
  - `algorithm=contours` accepts fractional `increment` (e.g. `0.05` for surface-reflectance COGs where TiTiler requires integer), and `histogram_bins` accepts floating-point custom bin edge lists (e.g. `0,0.1,0.2,0.5`).
  - Extra convenience endpoints & syntax: `/docs`, `/openapi.json`, `/cog/bounds`, `/cog/tilejson.json`, `/cog/map.html`, `/cog/WebMercatorQuad/WMTSCapabilities.xml`, `/mosaicjson/bounds`, `/mosaicjson/assets`, `/mosaicjson/statistics`, `/mosaicjson/bbox`, `/mosaicjson/feature`, and `@2x`/`@3x`/`@4x` retina tile scale suffixes.
  - Enriched metadata fields: `/cog/info` and `/mosaicjson/info` include `minzoom`, `maxzoom`, and `wgs84_bounds`; `GET /cog/stac` returns `application/geo+json` (the STAC Item media type).

### 1.9 Pure-Rust GCP Georeferencing, Ungeoreferenced & RPC-Only TIFF Support (`U2(b)`, `U3`, `MM1`)

- **TiTiler / GDAL:** On GCP-only GeoTIFFs (e.g. `odd/gcp_affine.tif`), GDAL's default GCP warper can disagree with the exact affine twin (`2088` vs `2600` at `-122.4, 37.8`). On ungeoreferenced or RPC-only (`RPCCoefficientTag 50844`, e.g. Pléiades/WorldView L1B) TIFFs, TiTiler returns `500 Internal Server Error` on `/cog/info`, `/cog/preview`, `/cog/tiles`, and `/cog/point`.
- **`cogzilla`:** Fits GCPs in pure Rust (zero C dependencies): when the order-1 least-squares affine residual is `< 0.05 px`, stores an exact `Affine2D` (zero runtime overhead on hot paths and bit-identical pixels/point values to the affine twin); otherwise fits a normalized order-2 (`>= 6` GCPs) or order-3 (`>= 10` GCPs) forward & inverse polynomial warp. Exposes `gcp_residual_px` in `/cog/info`.
- **Ungeoreferenced & RPC-only TIFFs (`U3`, `MM1`):** Serves `/cog/info` (`crs: null`, `bounds: null`), `/cog/validate` (full structural COG report with `GEO: null` and an explicit warning), `/cog/preview`, and `GET /cog/statistics` directly in pixel space, while returning `400 Bad Request` naming the missing georeferencing / RPCs on geographic routes (`/tiles`, `/point`, `/bbox`, `/feature`, `/bounds`).

### 1.10 Anonymous `s3://` Fallback & Cloud Credential Chain (Sweep #44, `PP1`)

- **TiTiler / GDAL:** Opening a public `s3://` URI without AWS credentials fails with `500 InvalidCredentials: No valid AWS credentials found`.
- **`cogzilla`:** Falls back automatically to unsigned HTTPS with S3 bucket-region discovery for public `s3://` buckets, while supporting static env vars, `AWS_PROFILE`, ECS task roles, EKS Pod Identity (`AWS_CONTAINER_AUTHORIZATION_TOKEN_FILE`), EKS IRSA (`AWS_WEB_IDENTITY_TOKEN_FILE` + `AWS_ROLE_ARN`), and EC2 IMDSv2 for private buckets.

### 1.11 Exact `grayscale` of Whole Numbers, and Unsigned `sum`

- **TiTiler:** `grayscale` sums `r*299/1000 + g*587/1000 + b*114/1000` term by term in float64 and truncates, so a grey picture stored as RGB (three equal bands) comes out one lower than its own value on about 5.5% of pixels (`0.299·a + 0.587·a + 0.114·a` lands just under `a`). `sum` over unsigned integer bands answers `500`.
- **`cogzilla`:** Sums whole-number bands exactly (`(r*299 + g*587 + b*114) / 1000`) before truncating, so equal bands give back their value, and writes `sum` of unsigned integer bands as `uint64`. Otherwise matches TiTiler's types, edge cases, and values (`ddof=1` spread with single-band `std`/`var` masked, `grayscale` requiring `≥ 3` bands, truncation, and `astype` wrapping for `cast`/`ceil`/`floor`).
- **Client significance:** Grey RGB imagery keeps its values through `grayscale`, and `sum` over unsigned bands succeeds where TiTiler fails.

### 1.12 A Fractional Contour `increment`

`algorithm_params` are checked as TiTiler's pydantic models check them (2026-11-26): each algorithm reads its own fields in pydantic's lax mode (`"45"`, `45.0` and `true` are the integer they spell), within its bounds, and passes over other keys; what it refuses is a `400` in pydantic's words (without the line that links to pydantic's documentation), and parameters that are not JSON are FastAPI's `422`, on the routes that apply an algorithm. One field is wider: `contours`' `increment` may be a fraction, for data whose values lie between whole numbers (reflectance, say), where TiTiler takes only a whole number. Parameters that are JSON but not an object, which TiTiler fails on with a `500`, are a `400` here.

### 1.13 The Overview of a Warped, Smoothed Read Is Chosen by Ground Size

A box, feature or statistics read into another projection with a smoothing method (`bilinear`, `cubic`, `average`, `lanczos`, ...) is, in rio-tiler, a read of a GDAL warped VRT at a size. GDAL chooses the overview by the least-reduced axis, as cogzilla does, but measures it in the VRT's own pixels: square in degrees (or Web Mercator metres), sized from the raster's diagonal. In degrees a pixel of longitude is shorter on the ground than one of latitude by `cos(latitude)`, so away from the equator GDAL can read an overview coarser than the output's pixels across. For example, a 64×43 box at 45.7°N has pixels of 146 m across and 207 m down; GDAL reads Sentinel-2's 160 m overview, and cogzilla reads the 80 m one with a kernel widened to each pixel's footprint. Whether GDAL drops a level then depends on the box's aspect: a 64×64 box over the same ground reads 80 m in both.

cogzilla keeps its choice. Against the area mean of the 10 m pixels (the ideal value of each output pixel), cogzilla's 64×43 box has RMSE 35 to 53 under `average`, `bilinear`, `cubic` and `lanczos`. GDAL's choice, made by titiler-pgstac or tried in cogzilla, has RMSE 70 to 88 for the same requests, and is blurrier: its spread is 211 to 226 against 247. So where the two choices differ, cogzilla's pictures and statistics are expected to differ from TiTiler's by being sharper (as in that test): 31 to 40 dB from titiler-pgstac at such sizes, with a higher `std` and a wider range. Where they agree (a 64×64 or 300×200 box), they match TiTiler's to 56 to 70 dB.

### 1.14 Native Zero-GDAL Zarr v2/v3 Support (`/zarr/*`, PR #359)

`/zarr/*` has left the parked list and now routes directly through the same `BandSource` + `cogzilla-kernel` + `zonal.rs` pipeline as `/cog/*` (zero parallel render pipeline):
- **Unified semantic HTTP statuses (#388):** Every `/zarr/*` failure maps through a single status table (`400` for missing/ambiguous variable listing available variables, out-of-range `sel` with available `[min, max]` never silently clamped, irregular/curvilinear grid naming dimension & index, named unmodellable CRS never silently falling back to `EPSG:4326`, or cap exceeded; `403` for upstream 401/403; `404` for missing store or out-of-bounds tile; `501` for unknown codec listing supported codecs; `502`/`504` for corrupt chunks, missing chunks without a fill value, or origin timeouts).
- **Pre-fetch DoS fan-out & decode caps (#386):** Covering chunk count (`COGZILLA_ZARR_MAX_CHUNKS_PER_REQUEST`, default `256`) and total decoded window bytes (`COGZILLA_ZARR_MAX_DECODED_WINDOW_BYTES`, default `256 MiB`) are checked from metadata before the first chunk GET.
- **Mutable-store freshness (#387):** Local stores validate on open via `stat(len, mtime)`, remote stores revalidate via `HEAD` after `COGZILLA_CACHE_TTL_SECS`, and `/zarr/*` ETags fold in the store metadata validator so revalidation after an append returns `200 OK` with fresh bytes instead of a stale `304`.
- **Exact analytical zonal stats & wide dtypes:** `POST /zarr/statistics` reuses `zonal.rs` (exact coverage & ellipsoidal area weighting), and `Int32`/`UInt32`/`Int64`/`UInt64`/`Float64` stay exact in `BandData::F64`.

### 1.15 Additional Correctness & Robustness Improvements Verified by Differential Oracle

Confirmed against stock TiTiler 2.4.1 (`rio-tiler 9.4.14`, `rasterio 1.5.2`) across 1,006 adversarial differential checks (0 CPU-vs-GPU diffs):
- **Inverted `rescale` ranges (`rescale=max,min`, e.g. `rescale=200,0`):** `rio_tiler.utils.linear_rescale` calls `numpy.clip(image, imin, imax)` which collapses every pixel to `imax` whenever `imin > imax`, rendering a flat constant tile (solid `255` gray or flat `viridis(255)`). `cogzilla` performs proper linear inversion across `[imin, imax]` on both CPU and GPU.
- **Extended GDAL `resampling=` modes (`min`, `max`, `med`, `q1`, `q3`, `sum`):** TiTiler 2.4.1 rejects these six modes with `422 literal_error`; `cogzilla` supports all 15 GDAL resampling modes across tiles and previews.
- **`color_formula` on single-band grayscale and colormapped imagery:** TiTiler crashes with `500` when `color_formula` (e.g. `Gamma RGB 1.8`) is applied to a 1-band COG (both plain grayscale and with `colormap_name=viridis`); `cogzilla` applies the formula cleanly and returns a valid `200` PNG on both CPU and GPU.
- **`0..360°` and antimeridian-crossing (`179°E..181°E`) geographic rasters:** For geographic COGs whose longitude bounds lie in `[180°, 360°]` or cross `±180°` (e.g. `179°E..181°E`), `cogzilla` wraps longitudes cleanly so both west (`179.5°E`) and east (`179.5°W`) `WebMercatorQuad` tiles and `/cog/point` queries succeed (`200`), where TiTiler returns `404` (`TileOutsideBounds` / `PointOutsideBounds`).
- **Exact polar TMS footprint checks:** On polar TileMatrixSets such as `UPSArcticWGS84Quad`, TiTiler's WGS84 corner-reprojection check can invert latitude bounds and return blank `200` tiles hundreds of kilometres outside the raster (e.g. `UPSArcticWGS84Quad/2/1/1` vs `EPSG:3413` COG 580 km away). `cogzilla` evaluates the densified footprint in native CRS, returning `404` outside the raster and bit-identical `200` tiles inside it.
- **Out-of-range `bidx` validation (`bidx=0` / `bidx > count`):** TiTiler crashes with `500 Internal Server Error`; `cogzilla` returns `422` / `400` naming the invalid band index.
- **Embedded palette COGs on `.npy`:** TiTiler unconditionally expands an embedded TIFF `ColorMap` into `(4, H, W)` RGB+mask on `.npy` with no query parameter to opt out, destroying raw integer class IDs for scientific/ML land-cover datasets (NLCD, WorldCover, CDL). `cogzilla` applies the embedded palette on visual formats (`.png`/`.jpg`/`.webp`) and preserves raw class indices `(2, H, W)` on `.npy` (matching `/point` and `/statistics`).
- **Rotated same-CRS GeoTIFFs (`ModelTransformationTag` on `EPSG:3857`):** When `src_crs == dst_crs == EPSG:3857` and the GeoTIFF has a non-zero rotation/shear (`b != 0` or `d != 0`), `rio-tiler`'s same-CRS tile read bypasses `WarpedVRT` and samples as if axis-aligned (misplacing values and dropping ~14% of valid pixels on a 30°-rotated tile). `cogzilla`'s `CoordPlan` checks `crs_to_pixel.is_axis_aligned()` and routes rotated same-CRS rasters through exact 2D affine sampling, matching exact ground-truth pixel coordinates.
- **Non-north-up GeoTIFFs — south-up (`e > 0`), East-to-West mirrored (`a < 0`), and pure 90°-rotated (`a = 0, e = 0`):** TiTiler 2.4.1 crashes with `500` on `/cog/bbox` (`float division by zero` for 90°-rotated `a = 0, e = 0`; `Bounds and transform are inconsistent` for south-up `e > 0` and mirrored `a < 0`), crashes with `500` on `POST /cog/statistics` for south-up and mirrored rasters, returns inverted `bounds` (`minx > maxx`) on `/cog/info.geojson` for mirrored rasters, and returns a false `404` (`Point is outside dataset bounds`) on `/cog/point` for mirrored (`a < 0`) rasters. `cogzilla` handles arbitrary invertible 2D affine transforms cleanly and returns exact `200` results with valid `minx < maxx` bounds across `/info.geojson`, `/bbox`, `/point`, and `POST /statistics`.
- **GCP-only `float32` GeoTIFFs (no GeoTransform, Ground Control Points only):** On `float32` GCP-only rasters, `rio-tiler` / TiTiler 2.4.1 corrupts its own mask to `-3.4028235e+38` (`f32::MIN` / `-FLT_MAX`) on `/cog/point` (returning `{"values": [null]}`) and renders a solid `viridis(0)` tile on `/cog/tiles/...png` (`MAE=61.0` vs GeoTransform ground truth). `cogzilla` fits the exact GCP transform in `cogzilla-tiff`, matching the equivalent GeoTransform raster bit-for-bit (`MAE=0.00, PSNR=99.0 dB` on `.png`, exact pixel value on `/cog/point`).
- **64-bit unsigned integer (`uint64`) GeoTIFF `.npy` tiles:** TiTiler 2.4.1 crashes with `500 Internal Server Error` when serving `.npy` tiles from `uint64` GeoTIFFs; `cogzilla` returns `200` with exact `<u8` (`uint64`) data and mask on both CPU and GPU.
- **Non-finite (`±Inf`) source pixels & expression domain/divide-by-zero masking:** On `float32` COGs containing `±Inf`, and on expressions producing `NaN`/`Inf` (e.g. `sqrt(negative)` or `b2 / where(b1 > 130, b1, 0)`), TiTiler leaves non-finite outputs marked valid (and paints opaque `viridis(0)` on `.png`). `cogzilla` cleanly masks `NaN` and `±Inf` as nodata/transparent on both `.npy` and `.png` across CPU and GPU.
- **`colormap_type=linear` custom JSON stop interpolation:** When given a sparse custom JSON colormap (e.g. 3 RGB stops at `0`, `128`, `255`) with `colormap_type=linear`, `cogzilla` linearly interpolates across all valid pixels, whereas TiTiler treats the JSON dict as discrete (~0.6% coverage).
- **`algorithm=aspect` and `algorithm=cast` `output_dtype`:** `cogzilla` provides `algorithm=aspect` (`0..360°` azimuth with seamless `buffer` & colormaps; TiTiler returns `422`), and honors `algorithm=cast` `algorithm_params={"output_dtype": "int16"}` (plus `dtype` alias) without modulo-256 wraparound, whereas TiTiler's `CastToInt.__call__` hardcodes `img.array.astype("uint8")` and silently ignores its own `output_dtype` field.
- **`GET /cog/info?crs=...`, `GET /cog/bounds?crs=...`, and `GET /stac/{tms}/WMTSCapabilities.xml`:** `cogzilla` reprojects `/cog/info` and `/cog/bounds` into the requested `crs=` (TiTiler ignores `crs=` on `/cog/info` and lacks `/cog/bounds`), and serves valid OGC WMTS XML on `/stac/{tms}/WMTSCapabilities.xml` (TiTiler returns `404`).
- **Negative custom `histogram_bins` edges & `/statistics?algorithm=slope` / `/cog/map?algorithm=hillshade`:** TiTiler 2.4.1 rejects negative custom bin edges (e.g. `histogram_bins=-20,50,150,250,400`) with `422 string_pattern_mismatch`, silently crops 3 px off every border on `GET /cog/statistics?algorithm=slope` (`122×122 = 14,884` vs full `128×128 = 16,384` pixels) and on OGC `GET /cog/map?width=64&height=64&algorithm=hillshade` (`58×58` vs requested `64×64`), and crashes with `500` (`Invalid shape ... for Coverage`) on `POST /cog/statistics?algorithm=slope`; `cogzilla` supports signed custom bin edges (`200` with exact counts), preserves the exact requested dimensions on `/statistics?algorithm=slope` and `/cog/map?algorithm=hillshade`, and rejects unsupported `POST /statistics` algorithms cleanly with `400 Bad Request`.

## 2. Deliberate API & Error-Handling Divergences

| Area | TiTiler 2.4.1 | `cogzilla` | Why |
|---|---|---|---|
| **Uniform semantic HTTP statuses** (all routes, all 13 TMSs) | Out-of-matrix `x`/`y` returns `404`; out-of-footprint non-Mercator tiles can return `200` empty | **`400`** when tile address is invalid for the grid (`x`/`y`/`z` out of matrix, unknown TMS, unsupported CRS); **`404`** with JSON detail naming tile & dataset bounds when valid address lies outside dataset footprint (exact densified-outline test, independent of TMS, including `/point`, `/bbox`, `/feature`); **`204`** empty body when inside advertised mosaic/STAC bounds with no covering asset; **`200`** only when inside footprint (including all-nodata pixels) | Makes status codes a semantic fact about the request rather than a quirk of the TileMatrixSet or framework. |
| **Mismatched `rescale` count** (`N4`, PR #161) | Silently accepts e.g. 2 rescale ranges for 3 bands | **`400 Bad Request`** naming the range count and band count (`0`, `1`, and `N` remain valid) | Silent leniency hides bugs on ambiguous input; explicit error is safer for clients. |
| **Safe size bounds & `pixel_selection` validation** (Sweeps #30, #45) | Silently accepts `max_size=-1` (1×1 PNG), `width=0` (ignored), unbounded `tilesize=4096`, and `pixel_selection=lastbandlow`/`lastbandhigh` on 1-band mosaics (blank image) | **`422`** for `tilesize > 2048`, `max_size < 0`, `width = 0`; **`400`** for `lastband*` on 1-band mosaics or `pixel_selection` on routes that cannot honour it (`/point`, `/info`, `/assets`) | Prevents silent wrong/blank output and unbounded memory allocations. |
| **Mosaic `/point` outside coverage** (`D1`/`M4`, PR #162) | `204 No Content` (empty body) | **`404 Not Found`** with JSON `{"detail": "No asset covers point (lon, lat)"}` (empty mosaic *tiles* stay `204`) | Point callers are scripts that benefit from a diagnostic body; `204` fits map tiles only. |
| **Unsupported CRS on `/tiles`** (`M1`, PR #167) | Returns `404` or GDAL error depending on route | **`400 Bad Request`** (`unsupported CRS`) uniformly across `/info`, `/bounds`, `/preview`, `/point`, and `/tiles` | Debugging blank map tiles immediately reveals the unsupported CRS instead of claiming "outside image bounds". |
| **Upstream HTTP & URI scheme errors** (`V1`–`V3`) | Returns `500` for upstream 403/404/5xx/network faults and treats unknown URI schemes as missing files | **`403`** (`origin refused access (HTTP 401/403)`) for upstream auth refusal; **`404`** for upstream 404; **`502 Bad Gateway`** for upstream 5xx, truncated body, redirect loop, unreachable host, or origin ignoring `Range` (`origin does not support HTTP range requests`); **`504 Gateway Timeout`** on upstream timeout; **`400 Bad Request`** naming unsupported `<scheme>://` URIs | Separates client mistakes (`400`), origin access/missingness (`403`/`404`), and upstream faults (`502`/`504`) from server bugs (`500`). |
| **Unsupported compression, predictor, sample format, or GCP count** (`#556`) | Returns `500` on unreadable compression/format | **`501 Not Implemented`** uniformly across `/cog`, `/stac`, `/mosaicjson`, `/searches`, and `/zarr` (while corrupt codec payloads return **`502 Bad Gateway`** and malformed headers/requests return **`400 Bad Request`**) | RFC 9110 `501` distinguishes a valid source using a feature this build does not implement from a malformed client request (`400`) or corrupt upstream payload (`502`). |
| **Referenced STAC/MosaicJSON asset failures & partial renders** (`W2`) | Returns `500` or `404` when an asset referenced inside a STAC item or MosaicJSON fails; silently drops failed mosaic assets | **`502 Bad Gateway`** naming the referenced asset whenever a STAC or MosaicJSON asset cannot be fetched (keeping `404` strictly for missing top-level documents and out-of-footprint tiles); attaches **`X-Failed-Assets`** response header listing skipped failed assets when a mosaic partially renders from remaining assets | Prevents conflating a missing referenced asset with an out-of-bounds tile (`404`) and makes partial mosaic renders observable to clients. |
| **Source freshness & cache invalidation** (`W1`) | Local files re-read via GDAL; remote files stay stale after replacement | Local files validated via `stat(mtime, size, inode)` on every open (instant re-read on overwrite/resize, `404` on delete); remote HTTP files send `If-Match` and verify `ETag`/`Last-Modified` on range responses (invalidating and retrying once on change so a read never mixes two versions), and revalidate conditionally (`If-None-Match`/`If-Modified-Since` → `304`) or expire after `COGZILLA_CACHE_TTL_SECS` (default `5` s) | Guarantees fresh data for both local and remote mutable sources without sacrificing warm-path performance. |
| **NaN under a `nodata` override** | With `nodata=X` on a float raster, GDAL counts NaN pixels as data: TiTiler's `.npy` mask marks them valid (its statistics and pictures still drop them) | NaN is always no data; `nodata=X` replaces only the raster's own sentinel (pixels equal to it become data, pixels equal to `X` are masked) | A NaN is never a value to draw or count; the mask agrees with the statistics and pictures. |
| **Validation error body shape** (`E3`) | FastAPI/Pydantic nested `422` dict schema | Clear, concise error messages (JSON `detail`) | Avoids coupling to FastAPI's internal validation format. |
| **Band keys in `/statistics`** (`P4`/`M6`) | `b1`, `b2`, … | Keeps `b1`, `b2`, … (ported scripts index by them) | Preserves drop-in compatibility for existing TiTiler scripts. |
| **Float64 `.tif` / `.npy` on multi-COG & mosaic paths** (`#396`) | Preserves full `float64` precision across multi-asset stacks | Single-COG `/cog/{tiles,bbox,preview}` Float64 requests preserve full `f64` precision; multi-COG and mosaic compositing paths (`render_multi_cog_tile`, `render_mosaic_scenes`, `render_catalog_mosaic_tile`) composite in `f32` and widen into `f64` containers (`RawF64`/`NpyF64`) | Keeps the mosaic/multi-COG hot path on compact `f32` slabs while still honouring the requested `float64` container dtype. |
| **`return_mask=false` on 1-bit mask & RGBA COGs** | Preserves underlying RGB collar bytes behind `mask=0` / `alpha=0` and strips the alpha channel | Zeroes masked pixels (`[0, 0, 0]`) at block-decode time; valid pixels match TiTiler (`MAE ≤ 0.19`) | Folding the mask once at decode keeps `BandData` / `BlockStats` branchless across all CPU/GPU/stats hot paths, and pixels behind `mask=0` are undefined JPEG/collar fill. |
| **2-band PNG (`bidx=1&bidx=2`)** | Returns `200` with `[b1, b2, mask]` stuffed into an `RGB` PNG (`return_mask=true`) or `LA` with `b2` as alpha (`return_mask=false`) | Returns `400 Bad Request` across all dtypes directing callers to `.tif`, `.npy`, or `.f32` | PNG has no 2-data-band color type; browsers premultiply `LA` alpha (destroying `b1` where `b2 == 0`) and `[b1, b2, mask]` as RGB is a GDAL driver artifact. |

## 3. Deliberately Out of Scope (Parked)

- **JPEG 2000 (`B7`):** Requires C++ codec dependencies (`OpenJPEG`) and is rare in Cloud Optimized GeoTIFFs. *(Pure-Rust LERC / LERC_DEFLATE / LERC_ZSTD **is** supported via PR #164 with zero C/C++ dependencies, verified bit-exact on 18 GDAL-written files.)*
- **Zarr assets in `/stac` and `/mosaicjson` (#390):** Deliberately deferred even as `/zarr/*` lands. The `/stac` and `/mosaicjson` asset layer resolves assets through the COG/TIFF reader, and a Zarr store requires a `variable` (and optional `group`/`sel`) that STAC has no settled convention for mapping to a render request. TiTiler keeps this same split (`titiler.xarray` serves `/zarr/*`, while `/stac` and `/mosaicjson` use `rio-tiler`'s COG path). Revisit once `/zarr/*` has shipped and STAC's datacube extension has a clean render mapping.
- **Antimeridian `west > east` geographic bboxes vs literal GeoJSON rings (Sweeps #26 DD1 & #34 EE1):** For geographic `coord_crs` (`EPSG:4326` / CRS84), cogzilla unwraps `minx > maxx` (`maxx += 360`) per RFC 7946 §5.2 across all 15 geographic bbox entry points (`/cog/bbox`, `/stac/bbox`, `/mosaicjson/bbox` sized and unsized, and `?bbox=` on `/cog/statistics`, `/cog/map`, `/stac/map`, `/stac/assets`, `/mosaicjson/assets`, `/cog/preview`) so requests like `179.5,-17.5,-178.5,-16.5` return the exact same pixels as `179.5,-17.5,181.5,-16.5` (where TiTiler returns an empty 1 px wide image). For projected `coord_crs`, `minx >= maxx` returns `400 Bad Request` stating that `minx` must be less than `maxx`. By contrast, GeoJSON polygon rings are read literally per RFC 7946 §3.1.9 (splitting an antimeridian-crossing polygon is the producer's responsibility, and refusing wide rings would reject legal GeoJSON such as a `-180..180` world rectangle).
- **Symmetric ±2-turn geographic longitude normalisation (Sweep #34 JJ1):** Every point and geographic bbox entry point (`/cog/point`, `/stac/point`, `/mosaicjson/point`, `/mosaicjson/point/.../assets`, and geographic bboxes) shares a single symmetric longitude normaliser (`normalize_geographic_lon`) that wraps finite longitudes within `[-720°, +720°]` into `[-180°, +180°]` identically eastward and westward, returning `404` for `|lon| > 720°` (where TiTiler returns `500` at e.g. `900.5`).
- **Query string `+` decoding (Sweep #34 HH1):** `url=` and `asset_href=` decode `+` as a space per `application/x-www-form-urlencoded` (with literal `+` encoded as `%2B`, matching `httpx`, `requests`, and `urllib.parse.urlencode`), while `expression=` accepts both `%2B` and hand-typed `+` (returning the exact sum where TiTiler 400s on raw `+` and mis-masks `%2B`).

## Progress

- **2026-11-26: GDAL's widened kernels when downsampling.** With `resampling` or `reproject` set to `bilinear`, `cubic`, `cubic_spline` or `lanczos`, a request that shrinks the chosen overview now filters like GDAL (`GWKResample` in the warper, `GDALResampleChunk_Convolution` in RasterIO): at `s` source pixels per output pixel the kernel support grows from `r` to `r * s` source pixels and each tap weighs `K(distance / s)`, normalised by the sum of the weights. Before, the fixed 2x2 / 4x4 / 6x6 kernels only saw the pixels next to the sample point and aliased when zoomed out. Like the GDAL warper, a scale within 0.05 of a whole number snaps to it, so 1:1 and upsampled requests keep the fixed kernels and their SIMD paths; `nearest` is unchanged. Measured against TiTiler 2.4.1 (GDAL 3.12.2) on the bench fixtures, PSNR over the data range:
  - Same-CRS tiles, bbox and previews (`mercator_4k` z11/z12, `geo4326_4k` bbox 300/1500 px, previews, `expression`): 47-73 dB before, 126-141 dB after (float32 rounding). `uint16` / `int32` interior tiles: 77-97 dB before, integer rounding after (max diff 1). Previews of rasters with `NaN` holes: 62-67 dB before, 84-100 dB after.
  - Reprojected tiles that shrink (`geo4326_4k` z10/z11): 41-61 dB before, 48-69 dB after; a reprojected bbox (`mercator_4k` to EPSG:4326): 64-70 dB before, 85-91 dB after. The rest of the reprojected gap is overview choice: for those tiles GDAL's warper read the overview just coarser than the output (7% coarser) where cogzilla reads the next finer one, and `nearest` differs by as much (40-51 dB). Upsampled and 1:1 tiles are unchanged (116-124 dB).
  - Near `NaN` holes cogzilla still renormalises over the valid taps, where GDAL carries the `NaN` through the sum and masks the pixel, so masks differ by a few pixels along hole edges (96-99% agreement). `/statistics` reads the overview grid directly and ignores `resampling` / `reproject`, so its numbers are unchanged.
  - The GPU shaders keep the fixed kernels, so shrinking convolution requests render on the CPU; `nearest`, 1:1 and upsampled requests still go to the GPU.
